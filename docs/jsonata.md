# JSONata in Fergi mappings

Status: spike. `src/Fergi.Jsonata` (.NET only) registers a `jsonata` function; the Python and JS bindings do
not exist yet. This page records what we know about running the same expression on each runtime. The data
comes from `tests/jsonata-conformance` (see its README to run or extend it).

## How it plugs in

A JSONata expression is a string, so a mapping that uses one stays plain data:

```fsharp
Rule.Compute { Fn = "jsonata"
               Args = [ Arg.Literal(Str "first & ' ' & $trim(last)"); Arg.Input("person", sel "") ]
               Dest = sel "/fullName" }
```

`Fergi.Jsonata.Jsonata.register` adds the function to a `Mapping`. The first argument is the expression, the
second is the context (`$`), and every argument after the expression is also available as `$args`. An
expression that yields nothing (undefined) is an error, not a silent gap.

The library lives outside the Fergi core because the core must stay Fable-safe. Under Fable, JS and Python
would each need a binding to their own JSONata library; those are not written.

## Hand-writing a mapping file

Mapping files are expected to be generated by a program, which quotes expressions correctly. If you write one
by hand, YAML treats some JSONata characters specially in a plain scalar: `: ` is a mapping, ` #` starts a
comment (the expression is silently cut short), and a leading quote, `{`, `[` or `&` changes the type. Use a
block scalar (`expr: |`) or quote the whole expression.

## Which implementations

| Runtime | Library | Version tested |
|---|---|---|
| .NET | `Jsonata.Net.Native` (MIT, no dependencies) | 3.0.0, based on jsonata-js 2.1.0 |
| JS / TS | `jsonata` (MIT, the reference implementation) | 2.2.2 |
| Python | `jsonata-python` (pure Python) | 0.7.1 |

Of the 90 cases in the suite, 73 give identical results on all three runtimes and 17 differ.

## The portable subset

Everything the suite marks portable is safe to rely on across runtimes. That covers path navigation and
filters, predicates, `$map`/`$filter`/`$reduce`, `$sum`/`$count`/`$max`/`$min`/`$average`, string functions on
BMP text (`$join`, `$split`, `$substring*`, `$trim`, `$pad`, `$contains`, regex `$replace`/`$match`),
`$merge`/`$spread`/`$each`/`$sift`/`$zip`/`$distinct`, object construction and grouping, the transform
operator, conditionals, positional variables, `$formatNumber`, `$formatBase`, `$toMillis` and `$fromMillis`
without a picture, key order, null handling, and singleton-array behaviour.

## Where they differ

Avoid these in a mapping that must behave the same everywhere.

| Area | Difference |
|---|---|
| Integers above 2^53 | JS rounds them (they are doubles). Python and .NET keep them exact on the way through, but arithmetic is double in JS and Python and exact 64-bit in .NET. |
| `$string` of a non-integer | 15 significant digits in JS and Python, 16 in .NET (`0.333333333333333` vs `0.3333333333333333`). |
| Whole floats from the input | `$string(2.0)` is `"2"` in JS and Python, `"2.0"` in .NET. |
| Non-BMP characters (emoji) | `$length` is 3 for `a😀b` in JS and Python and 4 in .NET (UTF-16 units). `$substring` can split the pair: .NET throws. |
| Case mapping | `$uppercase("straße")` is `STRASSE` in JS and Python, `STRAßE` in .NET. |
| `$sort` with equal keys | Python does not keep the input order; JS and .NET do. |
| `$number("NaN")` | JS and .NET raise D3030, Python returns NaN. `$number("x")` is D3030 in JS and .NET but a plain `ValueError` in Python. |
| `$base64encode` of non-ASCII | JS encodes Latin-1, Python and .NET UTF-8. |
| Date pictures | `$fromMillis(0, '[Y0001]-[M01]-[D01]')` is right in JS and Python; .NET applies C# format strings. |
| Null versus undefined at the top level | Python cannot tell a null result from no result; inside an expression it can. |

## Runaway expressions

An infinite or very deep recursion never returns in the JS and Python libraries unless you set bounds. Set
them on every evaluation:

- JS: `jsonata(expr, { timeout: ms, stack: depth })` (errors `D1012` and `D1011`).
- Python: `frame = expr.create_frame(); frame.set_runtime_bounds(ms, depth); expr.evaluate(ctx, frame)`.
- .NET: the library stops runaway recursion itself (`U1001`). I found no timeout option, so mappings from
  untrusted sources would need an external time limit.

The conformance runners use a 2 s timeout and a depth of 500.

## Open questions

- Whether a mapping file should be allowed to use only the portable subset (a lint) or any JSONata.
- The JS library's `evaluate` is async, which does not fit the synchronous `Function` type, so the JS target
  needs an async registry variant.
- Reading the expression's error position back into the Fergi error (`compute.failed` with the position inside
  the expression) is not done yet.
